### 需要一起调整的数据语义

`parse_diff3_conflict_text` 会把无冲突的合并内容同时加入左右栏，再分别加入当前 / 传入的冲突片段。因此，左右栏现有文本不是两个 Git 阶段 blob 的原始全文；当前草稿在未处理块内默认使用当前侧内容。

本次已读取原始当前、传入全文，以 libgit2 的上下文行关系映射冲突范围；结果保留自动合入的无冲突内容，未处理的重叠区域以共同祖先内容为起点。共同祖先面板显示当前块的原始内容。

## 本次实现

- `src/conflicts/workbench.rs` 负责 Pencil 工作台结构、菜单、块旁接受、结果应用和回退流程。宽窗使用 224px 文件区，窄窗通过文件菜单导航；三栏宽度和共同祖先高度使用 Kit 的 `h_resizable` / `v_resizable` 调整。
- `src/conflicts/editor.rs` 按仓库、文件、冲突会话维护三个 Kit Editor。左右只读，中间编辑；保留原生行号、选区、IME、剪贴板、横向滚动与撤销。程序化接受和 AI 回填使用差异片段替换，避免 `set_value` 清空撤销栈；块状态元数据随撤销还原。
- 颜色贯穿代码行，左右使用当前 / 传入主题色，结果用未处理 / 已处理语义色。行号始终表示原文实际行；连接线与分段滚动映射表示版本对应关系。
- Zed 的 `BlockProperties` 不属于本项目锁定的 Kit Editor API。本次块按钮放在紧邻代码的操作沟槽；未向原生文档插入虚假对照空行，因此不是逐行补齐空白的 IDEA Diff 布局，也不是 Zed 内联编辑器的逐像素复制。
- 结果块范围参照 Zed `side_range` 的边界偏向：空块包含新输入，非空块排除边界输入；跨块编辑收敛范围，避免下一次接受误删相邻块。
- 三方读取改为后台任务，读取结果校验仓库、会话及请求代际；失败显示原因并允许重新选择文件重试。写入成功后才标记草稿已应用；未处理块的解决确认继续保留。
- AI 回填额外校验原草稿及冲突会话。生成期间发生新编辑时保留建议，可在对应文件的更多菜单复制，不直接覆盖新结果。二进制、缺失阶段及仅工作区冲突保留各自回退操作。
