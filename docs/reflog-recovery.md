# Reflog 与恢复分支

在「历史」页选择「恢复记录」，可从本地引用日志查找仍保存在对象库中的提交，并创建指向该提交的本地分支。

## 使用方法

1. 选择 HEAD、当前分支、指定本地分支或全部本地来源。默认读取当前工作区的 HEAD，显示近 30 天记录。
2. 按操作时间选择近 7、30、90 天或全部时间，也可以搜索操作说明、引用、操作者、邮箱或完整 OID。
3. 选中一条记录，分别检查「操作前」与「操作后」。恢复目标使用该侧的完整 OID；操作说明不参与推测目标。
4. 对象可用时，选择「查看提交」预览提交信息、文件和差异。合并提交以第一父提交为差异基准。
5. 选择「从此提交创建分支」，确认工作区、完整 OID、来源与分支名称，再创建本地分支。
6. 创建完成后可选择「查看恢复分支」浏览内容；低高度窗口中的同一动作位于筛选区的「操作」菜单。

宽画布使用记录与详情双栏；窄画布用「记录 / 详情」切换。记录面板获得焦点时，方向键选择记录，Enter 打开详情，Esc 返回记录。筛选输入支持去抖搜索和 Enter；按钮、来源、时间及编码菜单复用 Kit 的键盘行为。

## 创建分支的边界

恢复只新增本地引用，不自动 checkout、reset，也不更新索引或工作区文件。存在未暂存修改、已暂存修改或索引冲突时，仍可创建恢复分支。

分支名称复用已有校验，已有引用不能覆盖。创建会重新检查仓库与 worktree 身份、目标提交对象，以及会因新增引用而改变 HEAD 解析的 unborn HEAD 名称；也检查已登记的其他 worktree。无法检查的工作树或异常 HEAD 链会保守拒绝。

进程内恢复写入按 common-dir 串行执行；最终引用写入通过 libgit2 的锁与“必须不存在”的条件完成。该互斥只协调本服务，其他 Git 进程仍可能同时操作仓库。

如果引用创建成功后核验或列表刷新失败，界面会保留已创建结果并给出提示；不会删除新分支或把写后异常当成“未创建”。

## 日志与对象的边界

- 日志是本地快照，刷新后才会重新读取；它不是永久备份。
- 一条记录的旧、新 OID 都可能是零值、缺失对象或非提交对象。只有当前本地可读取的提交才能用来创建分支；不在已加载历史图谱中不等于缺失。
- 不计算整个提交图的可达性，也不自动 fetch 对象。对象若已被清理，日志本身不能重建对象内容。
- 未提交修改通常不在 Reflog 中。
- HEAD 日志来自当前 worktree 的 git-dir，本地分支日志来自 common-dir。「全部」包含 HEAD 和现存本地分支，不保证找回已删除分支的日志。
- 当前支持 files 引用后端与 40 位完整 OID，不读取 reftable。

## 读取、分页与诊断

日志通过只读文件 API 获取，缺失日志不会创建文件。坏行、未完成的末行、无法按 UTF-8 解码的文本和局部不可读来源会明确诊断；不能把覆盖不完整的结果当成完整历史。文本损失解码不改变用于恢复的 OID。

每次读取最多接受 64 MiB 原始日志、20 万条有效记录，单行最多 256 KiB；整体预算超限会报错。读取期间可以取消；来源或文件元数据变化时会丢弃候选结果，最多自动重读一次。

时间与搜索在已读取快照中先筛选、再分页，每页最多 100 条。「加载更多」不是文件 IO 分页；同一次查询的时间边界保持固定。读取耗时不以分页控件掩盖。

本模块不新增保护引用、Reset 回滚、审计数据库或 AI 评审行为。
