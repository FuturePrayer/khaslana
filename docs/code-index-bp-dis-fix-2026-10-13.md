# bp-dis 索引问题修正与验证（2026-10-13）

本次依据 `bp-dis-index-issues.md` 修正当前源码。报告测试的 `D:/workspace/bp/bp-dis` 在本机不存在，因此以下结果来自可重复的最小样例，不代表原仓库的 225 处调用已全部验收。

## 修正

- 重载目标：Java 调用保存实参数量和局部类型证据，用声明、字面量、强转与对象创建区分可确定的重载。筛选限制在同一声明容器，保留语言、导入、作用域和私有可见性守卫；未知实参不能任取一个重载，也不能回退到导入的同名方法。
- 重载调用方：提取时保存所属定义的序号，合并时按序号映射实际节点，修正同名定义索引被最后一个重载覆盖的问题。同一行的不同定义也不会混为同一调用者。
- 实例接收者：参数、局部变量及字段声明提供类型，保留块作用域与 lambda 参数遮蔽；包名用于限定类型身份。复杂返回类型、继承、泛型及变参不等同于已完成编译器级解析。
- 增量：调用记录 KCALL3 保存类型证据，解析缓存包含实参和接收者信息；目标文件变化后，从持久化记录重解未修改调用方。仍读取 KCALL1/2。内容版本升级为 v7，工作区与提交快照沿用现有的一次事务重建流程，数据库 schema 保持 v4。
- MCP 输出：搜索默认 10 条，紧凑模式省略文档摘要，保留签名、精确限定名、位置与分页。调用链省略固定覆盖说明和可由行 `file_path` 恢复的重复调用路径，跨文件出向调用保留真实调用文件。`detail=full` 恢复完整结果；双通道保留且内容一致。工具描述保持英文，明确缺省字段语义。
- 查询开销：计数摘要随索引事务与代际提交，清单及状态不再每次扫描所有仓库的节点、关系表；无摘要的旧库回退统计。源码工具直接查询定义与源码，不再先遍历调用关系后丢弃。

`qualified_name` 保持完整，外部客户端可直接用于下一次精确查询。没有把删除外层 JSON 转义或 structuredContent 当成模型上下文压缩。

## 尚不能据此得出的结论

原 bp-dis 的全量 CALLS 数、6820 个有候选未解析调用及 427ms 清单耗时没有在本机复测；外部 Maven 模块没有源码定义时仍不建虚假关系。CALLS/符号比例不能独立证明完整性。

报告 Q4 的模型选工具行为无法由服务端强制修正；现有初始化指引继续要求先搜索定义，再查源码或关系，并核验覆盖。此次没有宣称其 34 次调用会自动改为索引调用，也未验收 GUI。

外部客户端需要挂载新 release 程序并重启连接；等待自动刷新，或调用 `refresh_index` 后轮询到 `index_status.needs_rebuild=false`，才能使用 v7 的关系结果。仓库路径与 repo 键不变。
